# 자동 검색과 한 단계씩 진행하는 화면 · 0.8.0

2026-11-15

## 바뀐 동작

- 장소명을 2글자 이상 입력하고 350ms 멈추면 자동 검색한다. 검색 버튼과 결과 팝업을 없앴다.
- 검색 결과를 입력창 아래에 바로 표시한다. 결과 선택 → 지도 확인 → 선택적 별명 저장 순서다.
- 반환된 결과 안에서 공백을 제외한 장소명 완전 일치, 앞부분 일치, 포함 순으로 정렬한다. 같은 등급은 네이버 순서를 유지한다. 전체 장소 데이터베이스에 대한 정확도 순위는 아니다.
- 최근 검색어 30개의 결과를 앱 프로세스 메모리에 보관한다. 서버 왕복 없이 같은 검색을 다시 보여준다. 앱 종료 후 보존하지 않는다.
- 입력이 바뀌면 기존 결과와 선택을 지우고, 이전 요청 결과가 뒤늦게 새 검색을 덮지 못하도록 막는다.
- 폰 첫 화면은 큰 방문지 찾기 버튼 중심이다. 장소, 사진, 적재, 차량 전송, 전달을 한 단계씩 진행한다.
- 주요 버튼은 최소 높이 76dp다. 모든 방문지 탭을 나열하지 않고 ‘방문지 변경’에서 선택한다. 사진 추가를 눌러야 촬영/앨범 선택이 나온다.
- 차량 전송을 기본 흐름으로 유지한다. 기존 위치·음성 도구는 보조 메뉴에서 접근한다.

## 참고한 공식 자료와 적용 범위

- [Google 공식 Compose 샘플](https://github.com/android/compose-samples): Material 컴포넌트, 상태에 따른 화면 구성 참고. 저장소 코드를 통째로 복사하거나 외부 스킬을 설치하지 않았다.
- [Android 검색 UI](https://developer.android.com/develop/ui/compose/components/search-bar): 입력 변경에 반응하고 입력창 아래에서 결과를 선택하는 패턴 적용. 현재 Naver 지도 화면은 View 기반이므로 해당 패턴을 EditText/스크롤 결과 목록으로 구현했다.
- [Render 무료 서비스](https://render.com/docs/free): 15분 유휴 후 휴면, 재시작 약 1분. UI와 캐시는 첫 서버 재시작 시간을 없애지 못한다. 이번 건강 상태 요청은 HTTP 200까지 13초 걸렸다. 유료 플랜 변경은 하지 않았다.

## 범위와 한계

휴대폰 APK만 갱신한다. 차량 APK는 기존 버전이다. 백그라운드 도착 알림은 이번 검색/UI 변경에 포함되지 않는다. 실제 초보 사용자를 모집한 사용성 조사가 아닌 에뮬레이터 검증이다.

## 검증

- phone debug APK/계측 APK 빌드 및 단위 테스트 성공.
- Android 35 에뮬레이터: TripFlowTest와 PlaceSearchConnectionTest 총 7개 통과(60.303초). 차량 전용 테스트 함수는 phone에서 조기 반환하므로 차량 실행 검증을 의미하지 않는다.
- 예시 방문지 → 사진 단계 → 미적재 상태의 다음 버튼 잠금 → 두 방문지 적재 → 차량 전송 → 전달 단계 확인.
- 실제 HTTPS 서버에서 수원월드컵경기장 자동 검색 → 주소 결과 선택 → 지도 저장 버튼 → 별명 창 확인. 검색 버튼이 없음을 검사한다.
- 초기 검증에서 단계 변경 후 보조 메뉴 접근 누락을 발견해 수정했다. 별도의 System UI 응답 없음 창은 에뮬레이터에서 확인 후 닫고 재검증했다.
- 첫 실행 화면을 직접 캡처하여 상단 겹침과 주요 버튼 표시를 확인했다.
