## 우선 검증 후보 — 처음 가는 반납 장소의 마지막 진입로

**가설.** 목적지 주소를 알아도 주차장 입구와 지정 반납 구역이 달라 초행 이용자가 정보를 다시 찾는다. 쏘카 공시는 반납 절차까지 입증하며, 헤매는 사람이 얼마나 되는지는 인터뷰와 관찰로 확인해야 한다. [2]

**첫 실험.** 한 곳을 직접 답사해 주소, 실제 진입로, 지정 구역을 기록한다. 초행 이용자에게 주소 안내만 제공한 경우와 진입로 안내를 추가한 경우를 비교한다. 잘못 진입한 횟수, 휴대폰 확인 횟수, 지정 구역까지 걸린 시간을 기록한다. 지하에서 위치가 불안정할 수 있으므로 진입 전 안내와 정차 후 수동 확인을 별도로 시험한다.

**시연.** 테스트 좌표에 접근하면 짧은 음성으로 입구를 안내하고, 정차 후 구역과 절차를 표시한다. 위치 SDK와 TTS는 후보 도구이며 정차 판정 신호·권한은 공식 문서와 에뮬레이터에서 검증한다. 처음에는 직접 조사한 샘플만 사용한다. 쏘카와의 제휴, 예약 API, 실내 정밀 측위는 가정하지 않는다. [5]

## 함께 비교할 두 후보

- **반복 방문 기사의 현장 메모.** 정차 후 입구와 인계 사항을 음성으로 남기고 다음 방문 전에 재생한다. 재방문 빈도, 현장 정보가 바뀌는 주기, 직원·고객의 개인정보가 섞이는지부터 확인한다.
- **충전·정차 중 가족용 짧은 콘텐츠.** 기존 픽조이와 창밖동화를 비교해 동승자 연령, 참여 방식, 출발 시 중단·재개라는 차이를 설계한다. 가족이 실제로 반복해서 겪는 대기 장면을 확인한 후 시연 범위를 정한다. [1, 6]

## 기획서에 옮길 근거와 지표

산업 동향에는 Pleos App Market이 국내 양산 차종에서 외부 앱을 제공한다는 사실을 넣고, 경쟁 분석에는 위 표에서 선택한 서비스와 실제 사용 흐름을 적는다. 문제 정의에는 팀의 관찰을 추가한다. 예를 들어 ‘반납은 지정 장소 주차 후 앱에서 완료한다’는 공시에, ‘초행 운전자가 입구를 지나쳤다’는 관찰 기록에 각각 출처를 단다.

월간 활성 사용자 추정은 대상 기간의 지원 차량 수, 목표 고객 비중, 설치율, 설치 후 월간 이용률을 나눠 계산한다. 차량당 이용자 수가 다른 공유차·업무차에서는 사람과 차량 수를 별도로 둔다. 각 값에 공개 수치·팀 가정·실험값을 표시하고 재이용률은 같은 사용자가 다음 반납 또는 방문에서도 기능을 썼는지로 측정한다.
