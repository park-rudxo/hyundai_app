# 챙겨가 공모전 기획서 초안
2026-11-05 · 앱명 가칭 · 개인정보와 동의·서명은 본인 작성

## 앱 한 줄 소개

챙겨가(가칭)는 출발 전 휴대폰으로 찍어 둔 짐을 방문지와 연결하고, 차량에서 출발 준비와 도착 후 전달을 확인하도록 돕는 Pleos 앱입니다.

## 기획 배경

한 번의 외출에서 여러 곳을 방문하면 물건을 집에서 챙기는 일과 알맞은 방문지에서 건네는 일을 각각 기억해야 합니다. 외가에 드릴 선물과 친가에 드릴 짐을 함께 실었더라도, 첫 방문지에서 다른 짐까지 내리거나 전달을 잊을 수 있습니다. 가족 방문뿐 아니라 친구에게 빌린 물건 반환, 모임 준비물 전달에도 같은 흐름이 생깁니다.
주목하는 문제는 ‘어떤 물건을 누구에게 가져가기로 했는지’를 이동 중 다시 떠올리는 수고입니다. 물건 이름을 일일이 쓰는 대신 사진을 방문지에 묶고, 준비·적재·전달 상태를 이어서 확인하도록 기획했습니다. 이 문제의 빈도와 사진 입력의 편의성은 인터뷰와 사용 과제로 검증할 가설이며, 아직 사용자 조사 결과는 없습니다.
SnapPack은 사진 기반 짐 목록을 제공하고, 기아 PBV는 목적지별 배송 물품 안내 시나리오를 공개하고 있습니다.[1][2] 조사한 공개 자료에서 개인의 다중 방문과 사진 짐 인계를 연결한 동일한 Pleos 앱은 확인하지 못했습니다. 차별화의 초점은 개인의 외출 준비부터 차에서 내릴 때까지 이어지는 사용 흐름입니다.

## 주요 기능과 차량 특화 요소

① 방문지별 사진 등록: 휴대폰에서 방문지를 선택한 뒤 짐을 촬영합니다. 물건명 입력은 선택 사항이며, 사진 한 장을 하나의 짐 또는 함께 전달할 묶음으로 등록합니다.
② 출발 준비: 사용자가 정한 예상 출발 시각 N분 전에 휴대폰으로 준비 알림을 보냅니다. 사진 촬영과 실제 적재는 구분하고, 실은 짐은 사용자가 ‘실었어요’로 확인합니다.
③ 도착 후 전달: 내비게이션의 경유지·목적지 도착과 주차 상태를 연결해, 이번 방문지에 전달할 사진만 차량 화면에 표시하는 것이 핵심입니다. ‘건넸어요’는 직접 누르며, 도착만으로 전달 완료 처리하지 않습니다. 주행 중에는 사진 확인과 체크 조작을 제한합니다.
④ 외출 전 확인 사진: 선택한 사용자는 가스레인지·조명 등의 상태를 출발 전에 촬영해 두고 주차 후 촬영 시각과 함께 다시 볼 수 있습니다. 과거 사진을 보관하는 기능이며, 현재 상태 판정이나 원격 제어는 제공하지 않습니다.
휴대폰은 촬영과 계획 입력을, 차량은 이동 맥락에 맞춘 확인을 담당합니다. 차량의 도착 정보와 주차 조건을 연결해 목록을 다시 찾아 여는 수고를 줄이는 것이 차량 특화 가치입니다.

## 주요 사용 시나리오

예시 사용자는 주말에 외가와 친가를 연속 방문하는 사람입니다. 출발 전 휴대폰에서 두 방문지를 정하고, 외가에 드릴 과일과 친가에 드릴 선물을 각각 촬영합니다. 출발 시각을 10시, 준비 알림을 20분 전으로 설정합니다.
9시 40분 알림을 받으면 사진 목록을 보고 짐을 싣고 ‘실었어요’를 누릅니다. 원하면 가스레인지 상태도 새로 촬영합니다. 차량에 연결한 뒤 오늘 방문지와 짐이 전달됐는지 확인하고 출발합니다.
외가에 도착해 주차하면 과일 사진만 확인합니다. 물건을 건넨 뒤 완료를 누르고, 친가에 도착해서는 선물 사진을 확인합니다. 방문 순서가 바뀌어도 짐은 원래 연결된 방문지에 남고, 방문 취소나 전달 보류는 사용자가 선택합니다.
통신이 끊기면 마지막 동기화 시각과 저장된 목록을 표시하고, 변경 내용의 동기화 여부를 구분합니다. 도착 신호가 없거나 주차 상태를 확인할 수 없을 때의 대체 확인 방식은 개발 과정에서 검증합니다.

## 개발 계획

구성: Kotlin 기반 Pleos 차량 앱과 Android 휴대폰 보조 앱을 우선 개발합니다. 휴대폰은 사진 촬영·방문지 연결·예약 알림, 차량은 오늘 방문지·적재 확인·전달 확인을 담당합니다. 사진, 방문지 ID, 상태를 기기 간 동기화하고 로컬에 캐시합니다. 기기 연결은 일회성 코드 방식을 우선 검토하며, 전송·권한·오프라인 복구는 구현 검증 항목입니다.
SDK 활용: NaviHelper의 경유지·목적지 조회 및 onWayPointArrived / onDestinationArrived 이벤트를 활용할 계획입니다.[3] 도착 대상과 등록 방문지를 대응시키고, Vehicle State에서 사용 가능한 주차 관련 신호와 권한을 확인해 표시 조건을 구성합니다.[4] 속도 0만으로 주차를 판정하지 않으며, 주행 중 사진 조작을 허용하지 않는 방식으로 설계합니다. 차량 제어·물건 자동 감지·AI 이미지 판독은 첫 버전에 포함하지 않습니다.
현재 확인 범위: 공식 Vehicle 샘플을 Pleos 에뮬레이터에서 빌드·실행하고 운전석 앞문 상태를 조회했습니다. 본 앱의 동작, 내비 도착 이벤트, 주차 판정, 휴대폰 연동은 아직 검증 전입니다. 시연 시 실제 SDK 입력과 모의 입력을 명시합니다.
개발 순서: 11/5~8 사진 등록·두 방문지·적재/전달 상태를 구현하고 핵심 SDK를 시험합니다. 11/9~10 동일 과제로 2명에게 입력과 확인 흐름을 시험하고, 11/11~12 결과 반영·기획서 수정·영상 촬영을 진행합니다. 11/13~14 새 설치와 재실행을 점검합니다. 11/8까지 자동 도착·주차 연동이 확인되지 않으면 정차 상태에서 직접 방문지를 선택하는 시연으로 범위를 줄이고 제한을 공개합니다.
사진은 사용자가 선택한 것만 저장하고 삭제 기능을 제공합니다. 완료 상태를 되돌릴 수 있게 하며, 실사용 주소·사진·인증정보는 공개 시연 자료와 저장소에 포함하지 않습니다.

## 기대효과 및 발전 가능성

초기 대상은 차량으로 여러 방문지를 오가며 선물·반환 물품·모임 준비물을 전달하는 개인입니다. 사진을 보고 준비하고, 도착한 곳의 짐만 확인하는 흐름으로 준비 누락과 전달 누락을 줄이고자 합니다. 사진 입력이 글 입력보다 항상 빠르다고 가정하지 않고 비교 검증합니다.
첫 검증은 두 방문지와 짐 네 개를 준비하는 동일 과제를 휴대폰 기본 메모와 시제품으로 수행하는 방식입니다. 참가자별 등록 시간, 잘못 연결한 물건 수, 전달 확인 누락 수를 기록하고 시행 순서를 바꿉니다. 2명의 결과는 초기 사용 사례로만 제시하며 통계적 효과나 실제 누락 감소율로 일반화하지 않습니다.
반복 이용은 자주 가는 방문지와 물건 목록의 재사용에서 기대합니다. 다음 외출에서 목록을 다시 사용하는지, 등록 부담 때문에 중단하는지 확인합니다. 외출 전 점검 사진은 매번 새로 촬영하고 과거 기록과 구분합니다. 출시 후에는 월간 핵심 기능 이용자 수와 최초 사용 후 30일 내 두 번째 외출 이용률을 추적할 계획입니다. 현재 MAU·Retention 실측치와 수요 기반 예측치는 없습니다.
향후 동승자 공동 준비, 카풀 하차 시 물품 전달, 취미 모임의 장비 반환으로 확장할 수 있습니다. 기본 개인 기능을 먼저 검증하고 공유·기록 관리의 추가 가치를 확인한 뒤 유료화 여부를 결정합니다. 반복 외출에서 도움이 되는 경험을 통해 Pleos 앱마켓을 계속 이용할 이유를 만드는 것이 목표이며, 구독 유지 효과는 추후 검증합니다.
